# Muse Edit

把准备材料、排版与文件交付交给脚本；阅读建议由你提出，用户在网页里确认。工作台不会调用模型、转写音频或发布内容。

预览使用随技能提供的工作台，不另做简化界面。保留顶部“导入课程包／导出本课配置／复制到公众号”，中栏直接展示两类封面与“本期发布交付包”，右侧保留图文、播客播放、播客原文三种预览。
当前工作台是独立实现：编辑实时生效，与原版“应用并折叠／取消”的提交方式不同；卡片和播客视觉也未逐像素复刻，不能向用户声称原版完全一致。
导入课程后以本次导入包为恢复建议基准，刷新后保留；恢复模块须同时恢复关联概念项与锚点。确认阅读层后显示发布检查，后续编辑撤销确认。
中栏模块与右侧内容保持联动：点开、编辑、开关和恢复模块时定位对应卡片；移除卡片后定位其原文锚点。结构地图和重点表达也应定位右侧，定位标记不能进入公众号复制产物。

自定义重点提供独立列表，可连续添加多处，添加后清空输入并显示下一处序号；保留逐条换格式和移除。匹配仍要求同一正文行内唯一出现，不支持互相重叠的启用规则；失败原因须在输入附近显示，不能丢弃已有重点。

## 入口

- **已有 Muse 课程 JSON**：直接校验、构建。兼容 schemaVersion `1.0`；素材根目录可能与 JSON 目录不同，用 `--assets` 明确指定。
- **新课程／固定 Muse 风格文章**：先读 [课程配置](references/course-format.md)，用 `init` 保留原稿，随后填写阅读层和节目笔记。纯图文可以不提供音频，关闭听音组件；品牌配图由用户提供。
- **普通文章要自由选公众号主题，或导入 gzh-design 排好的 HTML**：可用时交给 `gzh-design`。不把排好的 HTML 转回 Markdown 再声称保留原主题。只有用户明确选择 Muse 固定阅读风格时才走本工具。

运行需 Node.js 22+；脚本无 npm 运行依赖。下列 `<skill>` 替换为本技能目录，路径含空格时加引号。

## 生产流程

1. 读取原稿与现有素材。Markdown／UTF-8 TXT 可直接使用。DOCX／PDF 使用环境中可用的文档工具先转换并检查；扫描件须 OCR，不把提取缺失当成空白原稿。转换稿留作本次的基准原稿，原文件保留。
2. 新课程执行：

   ```bash
   node "<skill>/scripts/muse.mjs" init --source "原稿.md" --title "课程标题" --id lesson-01 --series "课程系列" --lesson 1 --out "工作目录" --audio "录音.mp3" --article-cover "图文封面.png" --podcast-cover "播客封面.png"
   ```

   三个素材参数均可省略；缺少素材时交付报告标记待补。不要伪造音频或时长。`init` 默认关闭阅读层；接着编辑 `工作目录/course.json`，不能把空建议骨架当作完整交付。
3. 按原稿语义填写适合的导读、概念、步骤、提醒、练习，以及重点原句和推荐理由。只启用本课真实需要的组件；不为了填满组件发明方法。新增阅读层与原稿分开，`transcriptMarkdown` 保持原样。规则必须唯一命中同一正文行，不能重叠；引文不重复输出。章节时间点仅在有真实时间码时另交付。
4. 校验并构建到新的输出目录：

   ```bash
   node "<skill>/scripts/muse.mjs" validate --course "工作目录/course.json" --source "原稿.md" --assets "工作目录"
   node "<skill>/scripts/muse.mjs" build --course "工作目录/course.json" --source "原稿.md" --assets "工作目录" --out "发布目录"
   ```

   完整课程发布材料验收加 `--require-assets`。若环境已有 gzh-design，可加 `--validator "其目录/scripts/validate_gzh_html.py"`；不自动下载或安装它。校验失败先修复再交付。结构检查与原稿匹配不能替代公众号手机预览。
5. 用浏览器打开 `发布目录/index.html`，核对全文首尾、阅读层、封面、音频和控制台。剪贴板受限时，仅在空闲端口启动该发布目录的本地服务：

   ```bash
   python3 -m http.server 8765 --bind 127.0.0.1 --directory "发布目录"
   ```

   先检查端口是否占用；不抢占其他项目端口。打开对应本地页面，用户原有浏览器标签不动。
6. 交付主入口、课程配置、原稿、HTML、音频／封面、节目笔记与 validation.json。说明哪些素材待补、检查覆盖了什么。浏览器调整后需“导出本课配置”留文件备份；再用导出 JSON 构建新目录，得到含修改的完整发布包。

## 真实边界

- 课程包不等于公开内容。对外分享技能只带工具与合成示例，用户课程、音频、角色原画留在用户指定工作目录；是否上传由当前任务授权决定。
- `index.html` 内嵌原稿与编辑脚本，可直接打开；图片和音频放旁边 `assets/`，迁移要复制整个文件夹。
- 草稿按页面路径、课程 id 和构建版本保存到当前浏览器。不会写回磁盘、跨浏览器同步，也不会自动覆盖 `article.html`；要用“下载当前正文”取得最新修改。
- 课程 JSON 可导回原 Muse 工作台，但本工具允许缺省素材和关闭组件的空锚点；旧工作台可能拒绝这种尚未补齐的草稿。本工具能直接接受原有完整 1.0 课程包。
- 当前 Markdown 是逐字稿子集：标题、普通段落、原有粗体、分隔线和围栏代码。复杂表格、内嵌 HTML、图片语法和链接语法不承诺富排版转换；遇到这类输入先检查预览，必要时转交 gzh-design。
- 音频需平台单独上传；不伪造原生播放器、逐句同步或平台发布成功。
